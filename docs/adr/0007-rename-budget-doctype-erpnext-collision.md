# Rename Budget DocType to Expenso Budget, migrate the shared table

expenso's `Budget` DocType (module `Expenso`) turned out to share its name with ERPNext core's own `Budget` DocType (module `Accounts`). Frappe has no collision detection for DocType names across installed apps (confirmed unchanged through v15/v16/v17-dev), so on any site with both apps installed — `22logic.com` in prod — the two apps silently shared one `tabBudget` table, each app's schema sync only ever adding its own columns and never removing the other's (issue #83). This wasn't just cosmetic: `BaseDocument.get_valid_dict()` only writes columns present in whichever app's DocType meta happened to sync last, so a `doc.insert()`/`.save()` from either app could silently drop the other's fields depending on sync order — a live correctness risk, not merely a display glitch (issue #84).

We renamed expenso's DocType to `Expenso Budget` rather than any alternative that would have required touching ERPNext's own code (not ours to change) or asking every affected site to uninstall/reinstall. A one-time migration patch (`expenso.patches.v0_0.split_expenso_budget_from_shared_table`) splits expenso's rows back out of `tabBudget` into the new `tabExpenso Budget` table and deletes only those rows, leaving any genuine ERPNext rows untouched. expenso's rows are identified positively — `category`/`amount`/`month`/`year`/`family` are columns that don't exist in ERPNext's own Budget schema, so a genuine ERPNext-created row can never have all five populated — rather than by any assumption about which columns are absent, since a plain expenso-only site never had ERPNext's columns to check against in the first place.

The patch deliberately does not drop `tabBudget` itself: on a site with ERPNext installed, ERPNext still owns and needs that table; on an expenso-only site it's simply left behind as an empty, harmless, orphaned table rather than risking a `DROP TABLE` against a table another app might still reference. The domain term "Budget" is unchanged everywhere user-facing (bottom-nav label, `docs/GLOSSARY.md`) — this is purely an internal Frappe DocType identifier change.

This fix ships to expenso's own codebase and dev sites. Actually running it against the real `22logic.com` prod backup is a separate, deliberate action (issue #83's own recommended step 4), not automatic from this change landing.
